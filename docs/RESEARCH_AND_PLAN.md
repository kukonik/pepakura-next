# Исследование и рекомендации для проекта Pepakura Next: отрисовка 2D-развёртки, интеграция AI и генерация 3D-моделей

## Главные выводы

1. **Отрисовка 2D-шаблона**: существующий код в `SplitView.vue` рисует «мозаику из треугольников». Чтобы добиться вида Pepakura Designer, нужно перейти на рендеринг только линий: контуры деталей (cut) — сплошная линия, линии сгиба (mountain/valley) — различные типы пунктира, клапаны (flaps) — отдельные многоугольники с управляемой геометрией. Все необходимые алгоритмы и параметры описаны в проекте `rodrigorc/papercraft` и в научных публикациях.

2. **Интеграция papercraft**: проект rodrigorc/papercraft (версия 2.12) является монолитным приложением на Rust с ImGui-интерфейсом и не предоставляет библиотечного API. Возможные пути интеграции: (а) форк/копирование кода (лицензия GPL-3.0) для использования алгоритмов в `pepakura_core`; (б) запуск papercraft как внешнего инструмента (OBJ → PDF/SVG) с последующим парсингом; (в) написание собственных реализаций на основе описанных алгоритмов.

3. **AI-агент и генерация 3D**: для анализа развёртки и оптимизации параметров можно построить LLM-оркестратор на основе Ollama (локально) с вызовом Rust-функций через Axum. Для преобразования текста/изображений в 3D-модели доступны готовые решения (Hunyuan3D, TriplaneTurbo, LGM и др.), которые экспортируют результат в OBJ, парсируемый через Rust-крейт `tobj` и подаваемый на вход `pepakura_core`.

## 1. Алгоритмы генерации клапанов (flaps)

**Результаты исследования:**

- В `rodrigorc/papercraft` клапаны определяются на уровне рёбер (edge-based): пользователь кликает по открытому ребру, чтобы переключить сторону клапана. Параметры: `flap_width` (мм), `flap_angle` (градусы, по умолчанию 45°), `flap_style` (`Textured`, `HalfTextured`, `White`, `None`). Также реализованы «теневые клапаны» (`shadow_flap_alpha`) для случаев склеивания снаружи.
- В научной литературе описаны автоматические методы: Korpitsch et al. (2020) используют симулированный отжиг для назначения клапанов (glue tabs) на MST-развёртке. Takahashi et al. (2011) предлагают алгоритм оптимизированной топологической хирургии для развёртки в один кусок.
- В Pepakura Designer настройка клапанов производится через диалог `Edit Flaps → Change Shape`, где задаётся `height` (мм) и `angle` (градусы) для всех или индивидуальных клапанов.
- **Рекомендация**: в `pepakura_core` необходимо идентифицировать граничные рёбра (boundary edges — рёбра, у которых только одна смежная грань) и вдоль них генерировать треугольные или трапециевидные клапаны с заданной шириной и углом боковых сторон. Можно взять за основу расчёт геометрии клапана (`FlapGeom`), реализованный в `craft.rs` (поля `tan_0`, `tan_1`, `width`, `triangular`).

## 2. Визуальная классификация типов сгибов (mountain/valley)

**Результаты исследования:**

- В системе Yoshizawa–Randlett (стандарт оригами) valley-сгиб обозначается пунктирной линией, mountain-сгиб — линией «тире-точка».
- В проекте papercraft для PDF/PNG используется: solid линия для mountain, dashed линия для valley. В SVG-экспорте линиям mountain назначается красный цвет, valley — синий.
- В Pepakura Designer, согласно опыту пользователей, mountain-линии отображаются сплошными, valley — пунктирными.
- Для автоматической классификации сгибов на 2D-развёртке нужно вычислить угол между нормалями соседних граней в 3D-модели: если угол > 0 — это mountain или valley в зависимости от знака (направления сгиба). В papercraft для скрытия почти плоских сгибов используется параметр `hidden_line_angle` (по умолчанию 3°).
- **Рекомендация**: в `pepakura_core` добавить классификацию каждого ребра развёртки как `Cut`, `MountainFold`, `ValleyFold` или `GlueTab`. На холсте Vue/Canvas 2D рендерить их разными стилями:
  - Cut — сплошная линия (ctx.setLineDash([]));
  - Mountain — сплошная (или dash-dot по желанию);
  - Valley — пунктир (ctx.setLineDash([4, 4])).
- Для векторного экспорта (PDF/SVG) можно использовать подход papercraft: отдельные слои для cut, mountain, valley.

## 3. Визуальный стиль 2D-шаблона (референсы)

**Результаты исследования:**

- **Pepakura Designer**: 2D-вид показывает только контуры деталей (outline), линии сгибов, клапаны и идентификаторы рёбер (edge IDs). Заливка треугольников отсутствует. Линии cut имеют один тип, линии fold — другой, клапаны отображаются как полупрозрачные области или только контуры.
- **Papercraft (rodrigorc)**: 2D-вид рисует текстурированные грани (опционально), контуры cut, линии fold, клапаны с текстурой или белые. При экспорте в SVG создаются отдельные слои: `Background` (текстура), `Cut` (отключён по умолчанию скрыт), `Fold` с подгруппами `Mountain` и `Valley`.
- **Инструмент PDOtools** (конвертация Pepakura PDO в SVG) генерирует для каждой детали замкнутый контур (outline) как единый объект, а линии сгиба — как отдельные пути, где valley – пунктир, mountain – сплошная.
- **Рекомендация**: для Vue-компонента `SplitView.vue` следует полностью переписать функцию `draw2D`, убрав заливку треугольников. Алгоритм отрисовки:
  1. Для каждого острова (island) собрать упорядоченный периметр (контур) из рёбер cut.
  2. Нарисовать контур сплошной линией.
  3. Нарисовать внутренние линии сгиба (mountain/valley) соответствующими пунктирами.
  4. Для каждого ребра с клапаном нарисовать многоугольник клапана (стиль: белый контур или полупрозрачная заливка).
  5. При необходимости нанести edge IDs (текст). Вся отрисовка должна выполняться через `CanvasRenderingContext2D` без заливки `fill()` для треугольников — только `stroke()` + опционально `fill()` для клапанов.

## 4. Интеграция проекта rodrigorc/papercraft

**Результаты исследования:**

- Анализ репозитория и файловой структуры показал, что `papercraft` — это монолитное приложение с точкой входа `main.rs` и без объявления библиотеки (`[[lib]]` в `Cargo.toml` отсутствует). Исходный код организован как модули `craft.rs`, `model.rs`, `printable.rs`, `ui.rs` и др.
- Проект не предоставляет API для вызова из другого Rust‑приложения. Весь функционал завязан на глобальное состояние `GlobalContext` и OpenGL/ImGui.
- **Варианты интеграции**:
  1. **Форк/перенос кода**: можно скопировать модули `craft.rs`, `model.rs` и часть `printable.rs` в `pepakura_core`, но это потребует соблюдения лицензии GPL-3.0 (весь проект `pepakura_next` тоже должен быть GPL-3.0). Алгоритмы развёртки, работы с островами, клапанами хорошо документированы в коде.
  2. **Внешний инструмент**: запускать `papercraft` как отдельный процесс, передавая OBJ и получая PDF/SVG. Однако это не даёт контроля над отдельными этапами (unfold, layout) и требует установки.
  3. **Референс**: использовать исходный код papercraft как источник идей для реализации собственных алгоритмов, не копируя напрямую защищённый код (если лицензия несовместима). Это наиболее гибкий путь для `pepakura_next` с текущим стеком (Rust + Tauri).

- **Рекомендация**: использовать вариант 3. Ключевые алгоритмы, которые стоит реализовать в `pepakura_core`:
  - Структура `Papercraft` с состоянием островов, рёбер и флагов клапанов (аналогично `craft.rs`).
  - Функции `edge_cut`, `edge_join` для интерактивного редактирования развёртки.
  - Алгоритм перестроения периметров островов (`island_perimeter`).
  - Генерация `FlapGeom` по параметрам `flap_width`, `flap_angle`.
  - Экспорт в PDF (используя `lopdf`, как в papercraft) или в SVG с слоями cut/fold.

## 5. AI-агент для анализа геометрии и оптимизации параметров

**Результаты исследования:**

- Современный подход к автоматизации инженерных задач с помощью LLM продемонстрирован в работе **TO-Master** (arXiv, июль 2026): LLM-агент на основе языковой модели (GPT-подобной) получает на вход mesh/геометрию/изображение, выбирает инструменты (проверка сетки, запуск солвера) и возвращает оптимизированные результаты.
- Для локального развёртывания в проекте `pepakura_next` предполагается использование **Ollama** (запуск моделей типа Llama3) с функцией вызова (`function calling`) через JSON-schema. Примеры такой реализации есть в репозитории `RuslanRakhmanin/Function_call_with_Ollama`.
- **Архитектура**:
  - LLM (Ollama) запускается рядом с Tauri-приложением или на том же хосте.
  - Приложение предоставляет Axum-эндпоинты (например, `POST /api/agent/analyze`), которые вызывают функции `pepakura_core` (статистика mesh: число граней, островов, углы сгибов, площадь и т.д.).
  - Агент в диалоге с пользователем или автоматически анализирует статистику, находит проблемы (слишком много мелких деталей, большие углы сгиба, неэффективное размещение) и предлагает новые значения для `UnwrapOptions` (например, `min_island_area`, `flap_width`, `merge_threshold`).
  - После согласования агент вызывает `unwrap_mesh` с обновлёнными параметрами.
- **Рекомендация**: реализовать модуль `ai_agent` со следующими компонентами:
  - `MeshAnalyzer` — вычисляет метрики (количество face, islands, boundary edges, гистограмму углов между гранями).
  - `AxumRouter` — регистрирует эндпоинты для вызова агента.
  - `AgentOrchestrator` — формулирует запрос к Ollama, парсит JSON function_call, вызывает нужные функции и формирует ответ пользователю.

## 6. Text-to-3D и Image-to-3D: API и формат передачи мешей

**Результаты исследования:**

- На июль 2026 года существует множество открытых моделей, способных генерировать 3D-меш по тексту или изображению:
  - **Hunyuan3D (Tencent)** — принимает текст или картинку, экспортирует в GLB/OBJ/FBX, поддерживает автоматическую ретопологию, до 10 000+ полигонов.
  - **TriplaneTurbo** (CVPR 2025) — text-to-mesh на основе дистилляции Stable Diffusion, не требует трёхмерных данных для обучения.
  - **LGM** (ECCV 2024) — многовидовые Gaussian → mesh.
  - **Zero123++** — zero-shot image-to-3D.
  - **MapAnything (Meta)** — универсальная реконструкция 3D по нескольким изображениям.
- Для интеграции в `pepakura_core` выбран **формат OBJ** как универсальный. Rust-крейт `tobj` (версия 4.0.4) позволяет загружать OBJ-файлы и извлекать вершины, нормали, текстурные координаты и треугольники.
- **Предлагаемая архитектура**:
  - Внешние generate-эндпоинты (через Axum или отдельный микросервис): `POST /api/generate/text3d` (принимает `{"prompt": "...", "options": {...}}`), `POST /api/generate/image3d` (multipart с изображением).
  - Эти эндпоинты вызывают подходящую внешнюю модель (можно через Python-сервис или прямой Rust-биндинг, если модель написана на Rust).
  - Результат (OBJ-файл или base64) передаётся в парсер `tobj`, который заполняет внутреннюю структуру `Mesh`.
  - Затем `Mesh` подаётся на вход `pepakura_core::unfold()`.
- **Рекомендация**: начать с обёртки для Hunyuan3D (API или локальный запуск) и реализовать конвертер OBJ → внутренняя структура через `tobj`. Первые две ветки (текст → 3D и изображение → 3D) можно сделать асинхронными задачами с сохранением прогресса.

## Итоговая рекомендация

Для достижения целей проекта Pepakura Next на текущем этапе (Alpha 0.7) предлагается следующий порядок действий:

1. **Немедленно (1–2 недели)**: переписать функцию `draw2D` в `SplitView.vue` для отображения только линий (cut solid, mountain solid/valley dashed) и клапанов. Использовать вычисленные из Rust данные `vertices_2d`, `faces`, `edge_classification`, `island_ids` и `flap_geometry`. Эту логику можно реализовать на TypeScript в Canvas 2D, получая данные через Tauri `invoke`.
2. **Краткосрочно (2–4 недели)**: реализовать в `pepakura_core` модули:
   - Классификацию рёбер (Cut, Mountain, Valley, FlapEdge) на основе угла между нормалями.
   - Генерацию контуров деталей (island perimeters) и геометрии клапанов (FlapGeom).
   - Экспорт в PDF с векторными линиями и классификацией (как в papercraft, но без зависимостей от OpenGL/ImGui).
3. **Среднесрочно (1–2 месяца)**: построить AI-агент (Ollama + Axum endpoint) для анализа развёртки и предложения параметров. Агент должен уметь объяснять пользователю результаты и возвращать новые `UnwrapOptions`.
4. **Долгосрочно (3+ месяца)**: интегрировать text-to-3D / image-to-3D, обернув Hunyuan3D или другую модель и подключив к пайплайну развёртки.

Все перечисленные решения опираются на изученные открытые источники и проверенные алгоритмы; отсутствие собственной библиотечной обёртки у `rodrigorc/papercraft` не является препятствием, так как ключевые идеи можно воспроизвести.
