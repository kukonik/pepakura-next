## Архитектурные решения

### 1. Условная компиляция
```rust
#[cfg(feature = "llm")]
pub mod local_llm;
```
- Модуль AI исключен из WASM-сборок
- Возможность отключения LLM для уменьшения размера бинарника

### 2. Синхронный HTTP-клиент
- Использование `ureq` вместо асинхронных клиентов
- Упрощение интеграции с Tauri и CLI
- Меньшая сложность кода

### 3. Модульная структура
```
pepakura_core/
├── ai/          # AI-функциональность
├── analysis/    # Анализ 3D-моделей
└── geometry/    # Базовые типы данных
```

### 4. Кэширование
- Встроенная система кэширования ответов LLM
- Уменьшение нагрузки на бэкенд
- Ускорение повторных запросов

## Технические характеристики

### Поддерживаемые LLM-бэкенды
1. **Ollama** (рекомендуется)
   - URL: `http://localhost:11434`
   - Поддерживаемые модели: qwen2.5:7b, llama3:8b, mistral:7b
   - Таймаут: 120 секунд

2. **llama.cpp** (через HTTP-сервер)
   - Совместимый API
   - Настройка через переменные окружения

### Требования к системе
- **Минимальные**: 4 ГБ RAM, 2 ядра CPU
- **Рекомендуемые**: 8+ ГБ RAM, 4+ ядра CPU
- **Для больших моделей**: 16+ ГБ RAM

### Производительность
- Анализ средней модели: 2-5 секунд
- LLM-запрос: 3-10 секунд (зависит от модели)
- Кэширование: ускорение до 10x для повторных запросов

## Решенные проблемы

### 1. CORS политика Ollama
**Решение**: Запуск с `OLLAMA_ORIGINS="*"`

### 2. Потребление памяти
**Решение**: 
- Использование меньших моделей (3b вместо 7b)
- Ограничение потоков: `OLLAMA_NUM_THREADS=4`
- Кэширование ответов

### 3. WASM-совместимость
**Решение**: Условная компиляция `#[cfg(not(target_arch = "wasm32"))]`

### 4. Ошибки сети
**Решение**: 
- Таймауты настроены (120 секунд)
- Повторные попытки подключения
- Детальные сообщения об ошибках
